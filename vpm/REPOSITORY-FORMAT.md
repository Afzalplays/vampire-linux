# Vampire package repository format (draft 1)

A repository root contains a signed `index.json`, its detached
`index.json.minisig` signature, and package archives.

## Index example

```json
{
  "format": 1,
  "repository": "vampire-stable",
  "architecture": "x86_64",
  "packages": [
    {
      "name": "hello-vampire",
      "version": "1.0.0",
      "description": "Example package",
      "architecture": "any",
      "license": "MIT",
      "depends": [],
      "url": "packages/hello-vampire-1.0.0.tar.gz",
      "sha256": "REPLACE_WITH_64_HEX_SHA256"
    }
  ]
}
```

The signature is generated by the repository maintainer with minisign and
verified by clients against a public key configured out of band. Never trust a
public key downloaded from the same unsigned repository as the index.

## Package archive

The current prototype accepts gzip-compressed tar archives containing files
relative to the target root (for example, `usr/bin/hello-vampire`). Absolute
paths, parent traversal, symlinks, hard links, device nodes, and special files
are rejected. Package maintainer scripts are not supported or executed.

This is a draft format. A stable specification must define version constraints,
dependency semantics, conflicts, file ownership, permissions, capabilities,
hooks, reproducible builds, rollback, and atomic transactions before release.
